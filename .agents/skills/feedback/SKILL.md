# Feedback — Manual Testing Session

Use this when the user brings feedback from manual UX/UI or feature/behavior testing.

## Step 1 — Restate before you touch anything

**Do not start changes.** First give your understanding of each feedback item: what the user wants changed or improved, and why. Flag anything ambiguous and ask about it. Both sides must be on the same page before moving on.

## Step 2 — Recommend

For each item, give your recommendation. If you know a better solution, present it as an option next to the user's original idea — each option with plain pros and cons, your preferred one marked with a ⭐.

## Step 3 — Cross-check

For each item, verify:

- **Existing decisions** — does it violate already-taken decisions (architecture, design, patterns, conventions)? If yes, say so and give options to choose from.
- **Planned work** — is it already planned for a future step (task/epic)? Point to it instead of duplicating it.
- **Effort** — estimate the heaviness with a score from 1 to 10.

## Step 4 — Group heavy feedback

If the feedback is large or heavy and can be grouped by nature, module, or behavior, split it into separate sub-tasks, each handling only its own topic.

## Step 5 — Confirm before executing

When everything is aligned, ask exactly: **"Can I proceed with the fixes?"** Wait for an explicit yes before executing anything.

Stay concise. Use plain human English.
